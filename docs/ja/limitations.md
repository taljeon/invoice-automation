# 実装範囲と残る制約

[English](../limitations.md) | [日本語](limitations.md) | [README](../../README.ja.md)

公開用ソースと標準デモを検討するための文書である。実装済みの保護機能、未実装の機能、実環境で未確認の事項を区別する。プロジェクト全体が本番運用に対応している、またはあらゆる請求書様式に対応しているとは主張しない。

## 1. 確認できること

| 領域 | ソースとデモで確認できる内容 | 別途、環境での検証が必要な内容 |
|---|---|---|
| UI | 合成PDF・明細、編集、行の追加・削除、履歴、ダウンロード | 実際の利用者に対するアクセシビリティ、各種ブラウザー・画面サイズ |
| CSV | 決められた列配置・検証・デモ用の割増計算・Shift-JIS変換 | 会計ソフトの各バージョン・設定でのインポート |
| サーバー構成 | jobの所有権、claim、renderer/OCR/LLMの接続コード | native renderer・実サービスの呼び出し |
| アクセス制御 | サーバー側token検査、ユーザー別パス、rulesソース | デプロイ済みのIAM/rulesと、ローカルで検証した規則が一致するか |
| 精度 | 合成入力に対する変換規則 | 実際の請求書のOCR精度・確認時間・費用 |

型検査と単体テストの成功は、外部サービス連携の成功とは別である。実施した検証結果は[verification.md](verification.md)に記録し、本書には未測定の処理時間・精度・削減率を記載しない。

## 2. 合成デモの範囲

- PDF 2件と明細3行をコードで生成する。既存の請求書ファイルを複製したfixtureではない。
- PDFは標準フォントで表示できる英語・数字を中心とするテキストで構成し、UI上の明細は日本語で構成する。
- 1行の数量を意図的に空欄とし、人がPDFを確認する手順を示す。
- 実際のOCR・LLM呼び出しは実行しない。任意のPDFから内容を抽出するオフラインOCRはない。
- ブラウザーのメモリーのみを使用するため、再読み込みするとデータ・編集内容・履歴は失われる。
- 新しい行は、メイン画面の全件一覧では最初の文書に、文書別の履歴ではその文書に関連付けられる。文書を別途選択するダイアログはない。

## 3. 業務規則の制限

1. 仕入先・顧客コードと商品コードは合成のlookupである。実マスターとの同期、承認済みの変更履歴、コードの有効性を管理する機能はない。
2. 名前の類似度が0.7以上の場合に会社を採用する規則は、誤ったマッチングを完全には排除しない。類似度は会計上の適合性やモデルの確信度を意味しない。
3. OCR promptの船舶例は3隻の合成船舶である。実際の文書群を汎用的に処理する、マスターに基づくprompt生成はない。
4. サーバーでの数量×単価による補正は、値引き・特別単価・返品の文脈を解釈しない。実際に値引きされた金額を乗算結果で上書きする可能性がある。
5. subtotal/total/tax/freight/feeを含む行をキーワードで除外する。実際の請求項目や正規の商品名も除外される可能性がある。
6. 単価・金額を読み取れなかった場合のnullは、変換時に0になる。0はCSVで有効な数値のため、数量を入力するだけでは価格の確認は完了しない。
7. セルのquantity、unit price、purchase amountはそれぞれ独立して編集される。数量を変更しても仕入金額は自動再計算されない。
8. 税率別の税額、免税、複数通貨、値引き、送料、返品、税抜金額・税額の照合を備える汎用会計エンジンではない。
9. `document_subtotal`の抽出を要求するが、明細合計と比較して承認の可否を決定することはない。
10. 伝票番号の生成・重複伝票の検証・会計ソフトでの伝票確定は実装していない。

## 4. CSVで特に確認すべき点

- 公開用コピーの100,000という閾値と10%・5%の割増率は、デモ用に作成した方針である。実際の契約や価格方針を示すものではない。
- 仕入合計を基準として、出力対象全体に適用するrateを選択する。同じPDFでも、ほかの文書と一緒にexportするとrateが変わる可能性がある。
- codeフィールドの直接編集と、CSVでの名前に基づくcode lookupは異なる。K/Pの最終値は[40列の仕様](csv-specification.md)で確認する必要がある。
- 空の日付・名前とnull・非有限数は拒否するが、不正な日付形式・未登録コード・有限の負数・数量と金額の不一致は自動的には拒否しない。
- カタカナの半角化とShift-JIS変換は、すべてのUnicode文字を保持するものではない。
- CSVのquote escapingは、スプレッドシートによる数式の解釈を防ぐ機能ではない。
- 税区分を含む複数の値は固定である。対象のインポート環境に合わせた個別の確認が必要となる。

## 5. ジョブの実行期間と障害復旧

クライアントは5分待機した後に終了し、関数は最大9分まで実行される。timeoutはキャンセルではない。サーバーでは完了したもののブラウザーが受け取れなかった結果を再購読したり、ユーザーの明細として復旧したりするUIはない。

Storage finalizeが複数回配信された場合、pending状態のみを対象とするtransaction claimにより重複実行を防ぐ。一方、実行中にインスタンスが停止してprocessing状態のままとなったジョブに対するlease/retryはない。失敗後の再処理では新しいjobが作成され、新しいjob同士でPDFの内容が同じかどうかは比較しない。

複数の明細行の保存・編集・削除は、順次リクエストを送信して行う。途中で失敗すると、一部だけが先に保存されている場合がある。画面にはエラーを表示するが、伝票全体のrollbackや補償transactionは提供しない。履歴を開き直して、実際の保存状態を確認する必要がある。

ジョブ結果をFirestoreの1文書内の配列に格納する構成のため、明細が多い文書や長い文字列を含む文書はFirestoreのdocument size制限に達する可能性がある。item数を最大1,000件に制限する検査は、バイト数の上限内に収まることを保証しない。ページ単位でchunkに分けて保存する構成はない。

## 6. 保管とアクセス制御

公開用コピーではユーザー別の明細パスとジョブ所有者の規則を使用し、保存時に過去の行を自動削除しない。一方、明細を削除しても元のPDF・OCR jobは同時には削除されない。TTL、保存期間、cascade delete、監査ログ、バックアップ・復旧を一括管理する機能はない。

明細のFirestore rulesは、ユーザー間の境界のみを検査する。各明細フィールドのschemaや数値をセキュリティルールで強制することはない。ユーザーが作成した明細を信頼できる精算台帳として使用するには、別途サーバー側で検証・確定する層が必要となる。

補助HTTP APIは、ID tokenと、必要に応じてファイル所有者を確認する。認証を追加したことだけで、ユーザー別の費用quota、rate limit、App Check、悪意あるPDF用のsandboxが完成するわけではない。処理量・料金・アクセス権限は、実環境に合わせて追加設定する必要がある。

15分間有効なsigned URLは、その有効期間中にファイルを読み取れるリンクである。恒久的な公開URLとして保存することはないが、外部共有の機能としても使用しない。有効期限と権限の境界は、運用環境で確認する必要がある。

## 7. サーバーとモデルの実行環境

- サーバーでのPDFレンダリングは、@napi-rs/canvasのnativeパッケージに依存する。ローカルの合成PDFレンダリングテストで確認した範囲と、実際のデプロイ環境との互換性は別途確認する。
- PDFには20MiB・20ページの制限と、ページごとのpixel数の制限がある。スキャン品質・暗号化・破損・特殊フォント・複雑なページへの完全な対応は保証しない。
- async Visionはページ単位で並列実行する。専用の同時実行プール、バックオフ、プロバイダー別の再試行方針はない。
- モデルの既定値は`gpt-5`だが、使用するアカウントでのモデルへのアクセス権限・料金・応答の互換性は別途確認する必要がある。
- JSON modeと型検証は、実際の文書に記載された事実の正しさを検証するものではない。欠落・文字の読み誤り・誤ったマッチングは、ユーザーが確認する必要がある。
- 標準のlocal emulatorコマンドは、end-to-end全体をemulatorに接続する構成を提供しない。

## 8. 参照コードとライセンス

過去のHTTP OCR、fuzzy matching、反復結果の比較、quality記録のコードは、構造を確認できるよう残している。現在のAppが使用する経路と同等の検証状態としては扱わない。従来のcodeList経路は、ブラウザーのAIキーによる呼び出しの代わりに、ローカルの合成マスターによるexact/fuzzy matchingを使用する。旧OCRクライアントには、サーバーが要求するBearer tokenの送信がまだ接続されていないため、そのまま有効な経路に切り替えることはできない。
