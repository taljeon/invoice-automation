# CSV 出力契約

[English](../csv-specification.md) · [日本語 README](../../README.ja.md)

基準となる実装は `src/utils/csvExport.ts` に集約されている。メイン画面と履歴画面は同じヘルパーを呼び出すため、列配置・文字処理・割増計算は共通である。ただし、各画面が渡す明細配列の範囲は異なる場合がある。

この仕様は公開デモの実装契約である。会計ソフトの全バージョンに共通する公式仕様や、インポート互換性の認証ではない。コードだけで列名を確定できない箇所には、推測した業務上の名称ではなく、実際の固定値と出典を記載した。

## 1. ファイル形式

| 項目 | 実装 |
|---|---|
| 列数 | 各行は厳密に 40 列、A〜AN |
| header | なし |
| 区切り文字 | カンマ |
| フィールドの quote | すべてのフィールドを `"..."` で囲む |
| フィールド内の quote | `"` を `""` に置換 |
| 行区切り | CRLF (`\r\n`)。最終行の後に追加の改行は付けない |
| 文字コード | `encoding-japanese` による Shift-JIS 変換 |
| BOM | 別途挿入しない |
| ダウンロード MIME | `text/csv;charset=Shift_JIS;` |
| 数値文字列 | JavaScript number の文字列表現。桁区切りなし |
| カタカナ | R、AN フィールドを独自 mapping で半角化 |

定義されたカタカナ・記号のみを変換する。漢字・ひらがな・すべての全角英数字を汎用的に変換する正規化機能ではない。Shift-JIS で表現できない文字、絵文字、一部の拡張文字の保持は保証しない。

## 2. エクスポート前の検査

`getExportErrors` は、行番号とともに次の項目を検査する。

- 空白だけの `商品名` または `仕入日`。
- null または有限数でない `数量`。
- 有限数でない `単価`、`金額`。

問題があれば生成関数はエラーを投げ、画面は修正を案内する。不明確な数量を 0 に置き換えてファイルを作ることはない。一方、明示的な 0、負数、小数は有限数として許可する。日付形式の正しさ、登録済みコード、数量×単価と金額の一致、税額は、この検査だけでは保証されない。

## 4. 合成名称→コード mapping

この mapping の値は、サンプルデータと構造を示すために作成したものである。

| 種別 | 合成名称 | 合成コード |
|---|---|---|
| 得意先 | サンプル一号 / サンプル二号 / サンプル三号 | 101 / 102 / 103 |
| 船舶略号 | 同じ 3 隻の船舶 | D1 / D2 / D3 |
| 仕入先 | サンプル部品株式会社 | 201 |
| 仕入先 | 架空機械株式会社 | 202 |
| 仕入先 | 例示商事株式会社 | 203 |

得意先・船舶の lookup は、完全一致を調べた後、入力に登録名称が含まれるかを検査する。仕入先は、完全一致の後に双方向の部分一致を使用する。複数の候補がある場合、リストの順序が結果に影響することがある。

- 得意先が未一致: `0000`。
- 船舶名がなければ空値。名前はあるが未一致なら、その名前をそのまま使用。
- 仕入先が未一致、または名前が空: `9999`。

現在の export は編集可能な code フィールド自体ではなく、**名称**を再 lookup する。メイン画面も履歴画面も同じである。実際の環境では mapping と承認手順を自分の master に合わせ、未一致コードをインポート可能な正常値と誤認しないようにする必要がある。

## 5. デモの売上ポリシー

顧客の実際の価格条件を含めないために、`DEMO_SALES_POLICY` に作成した合成ルールである。

```ts
threshold = 100_000
regularMultiplier = 1.10
volumeMultiplier = 1.05

purchaseTotal = sum(items.map(item => item.金額))
rate = purchaseTotal < threshold ? regularMultiplier : volumeMultiplier
salesPrice = Math.round(item.単価 * rate)
salesAmount = salesPrice * item.数量
salesTotal = sum(all salesAmount)
```

ちょうど 100,000 の場合は 1.05 を適用する。先に売上単価を整数に丸めてから数量を掛け、売上の行金額をもう一度整数に丸めることはない。quantity が小数なら、salesAmount も小数になり得る。JavaScript の `Math.round` は、正数の小数部分が 0.5 の場合、上の整数へ丸める。通貨の precision や負数に対する独自の丸め方針はない。

仕入 CSV は編集済みの `金額` をそのまま使うため、`数量 × 単価` と不一致でも自動補正しない。その不一致は基準合計に影響する。一方、売上 CSV では単価×数量から再計算するため、仕入金額に rate を掛けただけの値とは異なることがある。

## 6. 計算例

数量確認を終えた標準の合成データ:

| 文書・行 | 数量 | 仕入単価 | 仕入金額 | 適用倍率 | 売上単価 | 売上金額 |
|---|---:|---:|---:|---:|---:|---:|
| DEMO-001 / フィルター | 2 | 1,200 | 2,400 | 1.10 | 1,320 | 2,640 |
| DEMO-001 / パッキン | 1 | 8,000 | 8,000 | 1.10 | 8,800 | 8,800 |
| DEMO-002 / バルブ | 2 | 4,750 | 9,500 | 1.10 | 5,225 | 10,450 |
| 合計 | | | 19,900 | | | 21,890 |

バルブ行の数量は、最初は null と表示される。PDF の数量 2 を確認して入力するまで、その行を含む CSV は生成しない。PDF ごとの合計は、最初の文書が 10,400/11,440、2 つ目の文書が 9,500/10,450 である。

丸め順序の例: 単価 1,005、数量 3、rate 1.10 なら、`round(1,105.5) × 3 = 3,318` となる。仕入全体の 3,015 に 1.10 を掛けて一度だけ丸めた 3,317 とは異なる。UI の売上合計も、共通ヘルパーの**行ごとの計算結果の合計**を使用する。

出力範囲の例: 仕入 60,000 の文書と 50,000 の文書を個別に出力すると、どちらも 1.10 になる。しかし 2 文書をまとめて出力すると、対象合計が 110,000 なので 1.05 になる。このデモポリシーを PDF ごとに固定するには、ヘルパーのポリシー適用範囲を明示的に変更する必要がある。

## 7. ファイル名と利用上の境界

メイン画面では `仕入伝票_YYYYMMDD.csv`、`売上伝票_YYYYMMDD.csv` という名前でダウンロードする。履歴では `仕入伝票_<文書名>_YYYYMMDD.csv` のように文書名を含める。日付は実行時刻の ISO 日付から作るため、ローカル日付と UTC 日付の境界が異なる場合がある。

quote escaping は、カンマ・改行・引用符によって列が崩れることに対応するものである。表計算ソフトによる数式解釈を防ぐ汎用 sanitizer ではない。ユーザー入力を任意に変更すると伝票データも変わる可能性があるため、会計インポートと一般的な表計算ソフトでの閲覧の要件は、別々に決める必要がある。
